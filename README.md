# vpn — консольный клиент Xray для macOS

Лёгкий клиент для VLESS / VMess / Trojan / Shadowsocks из терминала: запускаешь `vpn` — открывается TUI со списком серверов, `Space` включает и выключает. Для скриптов есть обычные команды: `vpn on`, `vpn off`, `vpn status`.

Главное отличие от «больших» клиентов: **SSH никогда не идёт через VPN**. Порт 22, локальные сети и твои исключения всегда идут напрямую, поэтому `ssh` на свои серверы работает при включённом VPN.

> Статус: ранняя версия 0.1. macOS (Apple Silicon и Intel). На Linux работает всё, кроме автоматического системного прокси.

## Возможности

- Подписки от хостера (Marzban, Remnawave, 3x-ui и др.): base64 или список ссылок. Показывает остаток трафика и срок.
- Ссылки `vless://` (TCP/WS/gRPC/XHTTP/HTTPUpgrade, TLS и **Reality**), `vmess://`, `trojan://`, `ss://`.
- TUI: список серверов, вкл/выкл, пинг с подсветкой, выбор самого быстрого.
- TCP-пинг и **реальный пинг**: запрос через каждый сервер.
- Режимы: `global` (всё через VPN) и `ru` (российские сайты напрямую).
- Свои исключения: домены, IP, подсети.
- Системный прокси macOS включается и выключается сам. Для терминальных утилит есть `vpn env`.
- Ядро Xray-core скачивается автоматически, с проверкой SHA-256.

## Установка

1. Скачай бинарник под свой Mac из раздела Releases: `vpn-darwin-arm64` для M1/M2/M3/M4 или `vpn-darwin-amd64` для Intel. Можно собрать из исходников (см. ниже).
2. Установи его:
   ```sh
   chmod +x vpn-darwin-arm64
   xattr -d com.apple.quarantine vpn-darwin-arm64 2>/dev/null  # если скачан браузером
   sudo mv vpn-darwin-arm64 /usr/local/bin/vpn
   ```
3. Скачай ядро Xray. Этот шаг можно пропустить: `vpn on` сделает его сам.
   ```sh
   vpn setup
   ```

Ядро ищется в `~/.config/vpn/bin`, затем в Homebrew (`brew install xray`), затем в `PATH`.

### Сборка из исходников

Нужен Go 1.24+.

```sh
git clone <url-репозитория> && cd vpn
make build          # ./vpn под текущую систему
make dist           # dist/vpn-darwin-arm64 и dist/vpn-darwin-amd64
```

## Быстрый старт

```sh
vpn sub 'https://ссылка-на-подписку-от-хостера'
vpn          # TUI: выбрать сервер → Enter
```

Или без TUI:

```sh
vpn on       # включить
vpn test     # задержка и внешний IP
vpn off      # выключить
```

## TUI

| Клавиша | Действие |
|---|---|
| `↑` `↓` / `j` `k` | навигация |
| `Enter` | подключиться к выбранному серверу |
| `Space` / `o` | включить / выключить |
| `p` / `P` | TCP-пинг / реальный пинг |
| `b` | перейти к самому быстрому |
| `u` | обновить подписку |
| `m` | режим global ↔ ru |
| `s` | задать ссылку на подписку |
| `q` | выйти. **VPN продолжит работать**, выключить можно `vpn off` |

При первом запуске TUI сам попросит ссылку на подписку.

## Команды

```
vpn                    открыть TUI
vpn on [N] / off / toggle / status
vpn sub <url>          задать подписку и обновить
vpn update             обновить подписку
vpn add <ссылка>       добавить сервер вручную
vpn list               список серверов
vpn use N              выбрать сервер (если VPN включён — переподключится)
vpn ping [--real]      пинг всех серверов
vpn best               выбрать самый быстрый по реальному пингу
vpn test               проверить текущее подключение
vpn mode global|ru     режим маршрутизации
vpn direct add|rm|list <домен|IP|CIDR>
vpn sysproxy on|off    трогать ли системный прокси
vpn env [--off]        прокси для терминала
vpn setup              скачать/обновить Xray
vpn config / log / version
```

## Как это работает

```
 vpn (CLI / TUI)
     │  генерирует config.json, запускает и останавливает процесс
     ▼
 xray (в фоне)  ── SOCKS5 127.0.0.1:10808
                └─ HTTP   127.0.0.1:10809
     ▲
 системный прокси macOS (networksetup) → браузеры и приложения
```

- `vpn` не реализует протоколы сам. Всю криптографию и транспорт делает [Xray-core](https://github.com/XTLS/Xray-core), а `vpn` собирает для него конфиг и управляет процессом.
- xray запускается отдельным процессом в своей сессии. Закрытие терминала или выход из TUI VPN не выключает.
- Режим работы — **локальный прокси**, не TUN. Программы, которые уважают системный прокси (Safari, Chrome, Telegram и большинство приложений), идут через VPN. Остальные идут напрямую.

### Почему SSH работает

Обычно SSH при включённом VPN ломается по двум причинам. Клиент в TUN-режиме перехватывает весь трафик, включая порт 22, а VPN-сервер исходящий SSH режет. Здесь защита двойная:

1. Терминальный `ssh` вообще не использует системный прокси, поэтому идёт напрямую.
2. Даже если трафик попадёт в xray (например, через `vpn env` или proxychains), первое правило маршрутизации отправляет **порт 22 напрямую**. Так же напрямую идут приватные сети (`10/8`, `172.16/12`, `192.168/16`, `100.64/10` и т.д.), `localhost` и `*.local`.

Если твой SSH-сервер слушает нестандартный порт, добавь его адрес в исключения:

```sh
vpn direct add 203.0.113.7          # IP сервера
vpn direct add myserver.example.com  # домен и все поддомены
```

### Режимы

- `global` — всё, кроме исключений выше, идёт через VPN.
- `ru` — напрямую идут ещё `.ru`, `.su`, `.рф`, а при наличии geo-файлов (их ставит `vpn setup`) — `geosite:category-ru` и `geoip:ru`.

### Терминал

`curl`, `git`, `brew` и т.п. системный прокси не видят. Чтобы пустить их через VPN в текущей сессии:

```sh
eval "$(vpn env)"        # включить для этого окна терминала
eval "$(vpn env --off)"  # выключить
```

## Где хранятся данные

Всё лежит в `~/.config/vpn/` (переопределяется переменной `VPN_HOME`):

| Файл | Что внутри |
|---|---|
| `state.json` | подписка, серверы, выбор, настройки (права `0600` — там ключи) |
| `config.json` | сгенерированный конфиг Xray |
| `xray.log`, `xray.pid` | лог и PID процесса |
| `bin/` | xray, geoip.dat, geosite.dat |

## Решение проблем

**После перезагрузки Mac пропал интернет.** Системный прокси остался включённым, а xray после перезагрузки не запущен. Выполни `vpn off` или `vpn on`. `vpn status` предупреждает о такой ситуации.

**«порт 10808 уже занят».** Работает другой VPN-клиент. Закрой его или поменяй порты в `state.json`.

**Подписка не скачивается.** Если адрес подписки недоступен напрямую, включи VPN на любом сервере и повтори `vpn update`: при неудаче он попробует через VPN.

**xray отклонил конфиг.** Обнови ядро (`vpn setup`) и посмотри `vpn config`. Если ссылка рабочая в других клиентах, заведи issue, но **удали из ссылки UUID, ключи и адрес**.

**Системный прокси не включается.** `networksetup` может попросить пароль администратора. Чтобы не трогать системный прокси совсем, выполни `vpn sysproxy off` и пользуйся `vpn env`.

## Разработка

```sh
make test                         # unit-тесты
make test-xray                    # плюс проверка конфигов настоящим xray (скачает его)
make vet
```

Все файлы лежат в пакете `main`:

| Файл | Что делает |
|---|---|
| `link.go` | парсинг ссылок |
| `sub.go` | подписки |
| `xray.go` | генерация конфига и маршрутизация |
| `runner.go` | запуск и остановка xray, вкл/выкл |
| `sysproxy_darwin.go` | системный прокси macOS |
| `ping.go` | пинги |
| `setup.go` | установка ядра |
| `tui.go` | интерфейс |
| `main.go` | CLI |

В тестах — только фейковые UUID и ключи. **Никогда не коммить и не прикладывай к issue реальные ссылки и подписки.**
